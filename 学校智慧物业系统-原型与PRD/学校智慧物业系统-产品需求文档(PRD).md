# 学校智慧物业系统 — 产品需求文档（PRD）

> 版本：v1.0  
> 适用对象：学校物业公司管理层、演示客户、研发团队  
> 系统形态：网页管理端 + 微信小程序（用户端 / 员工端）

---

## 一、项目背景与目标

### 1.1 背景
学校物业管理的典型痛点：
- 报修渠道分散：电话、微信群、纸质单，难以追溯。
- 工单派发靠人工：响应慢、派单不均、无法量化员工绩效。
- 巡检难监管：校区面积大、固定巡检点多，无法证明员工是否到达指定位置。
- 数据缺失：维修量、响应时效、巡检完成率缺少可视化统计。

### 1.2 目标
建设一套**学校智慧物业系统**，实现：
1. 报修入口统一化（小程序拍照提交）。
2. 工单流转自动化（员工抢单/派单、限流控制）。
3. 巡检过程可证明（定位 + 时间 + 现场照片）。
4. 管理决策数据化（人员、工单、巡检多维度图表）。

## 四、功能需求

### 4.1 网页管理端

#### 4.1.1 登录与权限
- 支持 **管理员** 和 **领导** 两种角色登录。
- 管理员：拥有全部菜单权限（人员管理、系统配置、数据导出）。
- 领导：仅拥有数据看板与统计报表权限（只读）。

#### 4.1.2 人员管理
- **员工管理**：增删改查物业员工信息（姓名、手机号、工号、岗位、负责区域、账号状态）。
- **用户管理**：查看注册用户/临时报修人信息，支持黑名单。
- **角色管理**：配置管理员、领导、员工等角色权限。

#### 4.1.3 报修工单总览
- **列表视图**：
  - 字段：工单号、报修位置、问题类型、报修人、联系方式、图片、状态、接单员工、创建时间、完成时间。
  - 筛选：按状态（待接单 / 进行中 / 已完成 / 已关闭）、按时间、按位置、按员工。
  - 操作：查看详情、转派、关闭、导出 Excel。
- **统计图表**：
  - 工单总量 / 今日新增 / 待处理 / 已完成。
  - 趋势图：近 7 天 / 30 天工单量走势。
  - 环比图：本周 vs 上周、本月 vs 上月。
  - 饼图/柱状图：按问题类型、按区域、按员工处理量分布。
- **详情页**：工单全生命周期日志（提交 → 接单 → 处理 → 完成 → 评价）。

#### 4.1.4 巡检管理
- **巡检点管理**：增删改查巡检点（名称、位置描述、经纬度、二维码/Beacon/NFC 标识、巡检周期）。
- **巡检记录**：
  - 列表：巡检人、巡检点、定位结果、巡检时间、现场照片、异常说明。
  - 筛选：按日期、按员工、按巡检点、按是否正常。
- **统计图表**：
  - 巡检次数趋势图。
  - 各巡检点完成率 / 漏检率。
  - 员工巡检排名。
  - 定位偏差分布图（正常 / 轻微偏差 / 严重偏差）。

#### 4.1.5 系统配置（管理员）
- 工单类型配置：水电 / 门窗 / 地面 / 家具 / 空调 / 其他。
- 校区/楼栋/位置配置。
- 巡检规则配置：每人最大进行工单数、巡检有效半径、是否需要拍照。

### 4.2 用户端小程序

#### 4.2.1 登录方式（扫码进入，二选一）

小程序通过**微信扫码**进入，入口页提供两种路径；网页管理后台仅限管理员 / 领导账号登录（见 4.1）。

| 方式 | 流程 | 说明 |
|------|------|------|
| **方式 A：注册并登录** | 微信授权注册 → 登录 → 报修时联系方式自动回显 | 适合常驻学生/教职工，体验更好 |
| **方式 B：直接报修（免注册）** | 入口页点「直接报修」 → 填联系方式 → 拍照 → 提交 | 适合临时访客/不愿注册的用户；提交后仅可看工单进度，其他模块不可见 |

**访客与工单的后台关联**：访客提交时填写的手机号写入工单 `reporter_phone`；① 访客凭工单号在「我的工单」查进度；② 用同一手机号 + 验证码登录/注册后，系统按手机号自动归集其全部历史工单；③ 扫码携带的临时匿名 token 可一次性关联，注册后合并到账号。


#### 4.2.2 报修流程（必须拍照）
1. 选择报修位置（食堂 / 教学楼 / 宿舍 / 体育馆 / 其他，支持手动补充）。
2. 选择问题类型。
3. **拍照上传（必填，至少 1 张，最多 6 张）**。
4. 填写问题描述。
5. 填写联系方式（注册用户自动回显，游客必填）。
6. 提交工单 → 系统返回工单号 → 可查看处理进度。

#### 4.2.3 我的工单
- 列表展示本人提交的所有工单。
- 状态：待处理 / 处理中 / 已完成。
- 可查看详情、催单、确认完成、评价。

#### 4.2.4 通知
- 工单被接单、处理完成时推送微信订阅消息或短信（演示环境可用模拟通知）。

---

### 4.3 员工端小程序

#### 4.3.1 登录
- 员工账号登录（由管理员在网页端创建）。

#### 4.3.2 工单大厅
- 展示所有待接单的报修工单。
- 每个工单显示：位置、问题类型、图片缩略图、报修时间。
- **接单按钮**：点击接单，进入「我的工单」列表。

#### 4.3.3 接单规则（重点）
- 每个员工 **最多同时持有 2 个进行中的工单**。
- 只有完成或关闭 1 个进行中工单后，才能接新的工单。
- 已被接的工单对其他员工显示「已被接」状态，不可重复接单。

#### 4.3.4 我的工单
- **进行中**：查看已接工单，上传处理前/后照片，标记完成。
- **已完成**：历史工单记录。

#### 4.3.5 巡检功能
- 查看当日巡检任务列表。
- 到达巡检点附近 → 按系统要求完成定位核验 → 拍照 → 提交巡检记录。
- 支持异常上报（如发现损坏，可一键转报修工单）。

## 五、重点方案：巡检位置核验

校区面积大、固定点多，必须能证明员工到达了指定位置。提供以下 4 种可落地方案，可按预算与精度要求组合使用。

### 方案 1：GPS 定位 + 电子围栏（推荐，成本低）

**原理**：员工到达巡检点附近，小程序调用微信 `wx.getLocation` 获取经纬度，后端比对与巡检点坐标距离。

**实现要点**：
- 网页端为每个巡检点配置经纬度和有效半径（建议 30~100 米）。
- 员工端提交巡检记录时，后台计算两点距离：
  ```
  distance = haversine(员工经纬度, 巡检点经纬度)
  if distance <= 有效半径:  通过
  else: 不通过，要求重新定位或备注说明
  ```
- 同时上传现场照片 + 时间戳，形成「时间 + 地点 + 影像」证据链。

**优点**：无需额外硬件，部署快，成本低。  
**缺点**：室内/高楼遮挡下定位误差较大（可能 10~50 米）。  
**适用**：室外巡检点、预算有限、快速上线。

---

### 方案 2：定点二维码扫码核验（精度高，成本低）

**原理**：在每个巡检点张贴/悬挂专属二维码，员工到达后扫码，系统识别二维码 ID 与巡检点匹配。

**实现要点**：
- 每个巡检点生成唯一二维码（包含巡检点 ID）。
- 员工端调用 `wx.scanCode` 扫码，上传二维码内容 + 定位 + 照片。
- 后端校验二维码是否属于该巡检点，并记录扫码时间。

**优点**：能证明员工确实到达了二维码所在位置，精度高。  
**缺点**：需要打印/制作/维护二维码，存在二维码被拍照后远程作弊的风险。  
**防作弊建议**：扫码时强制同时上传一张带时间水印的现场照片 + GPS 定位，后台交叉校验。

**适用**：室内外固定设施、配电房、水泵房、食堂后厨等重点点位。

---

### 方案 3：蓝牙 Beacon 近场核验（室内精度高）

**原理**：在巡检点部署低功耗蓝牙 Beacon 设备，员工进入 Beacon 信号范围后，小程序检测到指定 Beacon 信号并上报。

**实现要点**：
- 每个巡检点配置 1 个 Beacon（UUID + Major + Minor 唯一标识）。
- 小程序使用蓝牙 API 扫描附近 Beacon，匹配到目标 Beacon 后允许提交巡检。
- 后端记录 Beacon ID、信号强度（RSSI）、时间、照片。

**优点**：
- 室内定位精度高（1~3 米）。
- 不易被远程伪造（必须靠近设备才能扫描到）。

**缺点**：
- 需要采购 Beacon 硬件（单价 20~80 元）。
- 需要定期更换电池（一般 1~2 年）。

**适用**：教学楼走廊、机房、配电室、食堂操作间等室内重点点位。

---

### 方案 4：NFC 触碰核验（最高防作弊，适合重点点位）

**原理**：在巡检点贴 NFC 标签，员工用手机触碰标签，读取唯一 ID 后提交巡检。

**实现要点**：
- 每个巡检点配置防金属 NFC 标签（NTAG213/215）。
- 员工端调用 NFC API（Android 支持较好，iOS 有限制）读取标签 UID。
- 后端校验 UID 与巡检点绑定关系，记录触碰时间。

**优点**：
- 必须物理触碰，防作弊能力最强。
- 标签成本低（2~5 元/张）。

**缺点**：
- iOS 微信小程序对 NFC 支持有限，主要适合 Android 巡检手机。
- 标签可能被转移，建议贴在高处或封装的巡检牌内。

**适用**：高配要求、重点机房、高配配电房等关键位置。

---

### 推荐组合策略

| 场景 | 推荐方案 | 说明 |
|------|----------|------|
| 快速上线 / 预算低 | 方案 1（GPS + 照片） | 零硬件成本，1~2 天可跑通 |
| 常规室内点位 | 方案 1 + 方案 2（GPS + 二维码） | 二维码低成本提高精度 |
| 重点机房/室内 | 方案 1 + 方案 3（GPS + Beacon） | 室内精度高，防作弊强 |
| 最高安全要求 | 方案 2 + 方案 4（二维码 + NFC） | 双重校验，适合关键设施 |

**MVP 阶段建议**：先用 **方案 1（GPS）+ 方案 2（二维码）** 组合上线，后续根据客户反馈逐步引入 Beacon/NFC。

## 六、关键业务规则

### 6.1 工单状态流转
```
待接单 → 已接单（员工 A） → 处理中 → 已完成（待评价） → 已评价
  ↓           ↓                ↓
已关闭     转派给 B          无法处理可关闭
```

### 6.2 员工接单限流规则
- 员工同时进行中工单上限：2 个。
- 达到上限时，「接单」按钮置灰，提示「请先完成当前工单」。
- 工单超时未处理（如 2 小时）可自动释放回大厅（可配置）。

### 6.3 报修必填项
- 位置：必填。
- 问题类型：必填。
- 照片：必填，至少 1 张。
- 联系方式：游客必填，注册用户自动回显。

## 八、非功能需求

### 8.1 性能
- 网页端列表页支持分页，默认 20 条/页。
- 图片上传后做压缩/缩略图处理。
- 首页数据看板接口响应 < 1s。

### 8.2 安全
- 用户端游客报修需验证码防刷。
- 员工端操作需登录鉴权。
- 图片文件存储路径不可遍历。

### 8.3 扩展性
- 巡检核验方式通过配置开关控制，后续可新增 Beacon/NFC 而不改表结构。
- 问题类型、校区位置支持后台配置。

### 8.4 演示适配
- 演示环境支持手动录入测试数据。
- 可一键生成模拟工单/巡检记录用于图表展示。

## 十、给客户演示时的重点话术

1. **统一报修入口**：“学生和教职工不用打电话、不用加群，打开小程序拍个照就能报修，位置、照片、联系方式一次齐全。”
2. **工单透明可追**：“领导在网页端能看到每张工单谁接的、什么时候到的、什么时候处理完，全程留痕。”
3. **防止员工偷懒**：“系统限制每人最多同时处理 2 单，防止有人把好接的单子全抢走，也能倒逼大家尽快完工。”
4. **巡检有证据**：“我们有 GPS + 二维码 + Beacon + NFC 多种核验方式，可以根据校区预算和重点程度灵活选择，保证员工真的到了现场。”
5. **数据说话**：“维修量趋势、响应时效、巡检完成率全部图表化，给学校领导汇报时一目了然。”
